# 项目长期记忆：LangGraphAgent 笔记库

## 笔记写作风格偏好（用户明确要求）
- **理论系统化 + 代码作验证（最终偏好，覆盖早期"先理论后实战"和"理论代码交织"）**：理论讲解以知识本身为核心，按"概念定义 → 背景动机 → 核心原理 → 推导过程 → 适用条件与边界"系统阐述，不要受项目其他文件或既有代码影响而一直围绕具体代码展开。代码仅作为理论讲完后的辅助示例/验证手段，应简化实现细节，并明确写出"这段验证前文哪条理论"。环境准备放最前面，不设"实验一/二/三"章节。先讲 Agent 与 LLM 区别，再介绍 LangChain。
- **理论顺序**：讲 Agent/LangChain 时，先讲 Agent 与 LLM 的区别，再介绍 LangChain 框架。
- **图文结合**：理论知识点用图辅助讲解，配图用图像模型生成新的教学插画风格图（中文标注），输出到对应笔记的 `images/` 目录；实战部分（代码、输出示例）不插图，保持原样。
- **章节编号**：参考入门 06（Skill调用）与 10（任务规划）篇，用 `N.x` 二级、`N.x.x` 三级编号；结构为"理论 → 运行准备 → 实战 → 小结"。
- 改写既有笔记时：原文代码、表格、链接、关键讲解必须零丢失，只做重排与必要 rewording；生态/分工类表格应从文末前移到理论部分。
- **开头风格**：不喜欢"我们会先…再…最后…"这种罗列文章路线、剧透结构的开头（像念大纲）；偏好问题驱动的开头——保留一个好的设问钩子，用几个问题引出全文，再一句自然带出"概念+代码交织"的写法。
- **去 AI 味（语言层面）**：不要用 `**概念定义。** / **背景动机。** / **核心原理。** / **推导。** / **验证：**` 这类填表式加粗标签，内容用自然段落过渡；避免"这正是……""不是 X 而是 Y""值得注意的是"等套路句反复出现；不要每段结尾都强行收束一句。保持六个理论维度的内容，但用工程师写笔记的口吻讲，不贴标签。
- **面向社区的教程写法（最新，覆盖"环境准备放最前"）**：面向第一次阅读的读者，开篇先讲整体目标、理论背景和"你会得到什么"，不要一上来就 `uv sync --locked` 这种依赖现成仓库的命令。以**新建项目**为主线：先理论背景 → 再从空目录 `uv init` / `uv add` / 目录树 / `.env` → 然后理论块与验证代码交替推进。原有命令要保留，但要补一句"已有配套仓库时怎么做"。语言贴近技术社区（用"你"、给运行命令、说明每个依赖的用途），核心观点与技术细节不变。
- **系列与目录结构对齐真实项目**：系列名是"LangChain入门笔记"，第一篇要在开篇点明。教程里的项目结构必须和当前真实项目趋近一致——根目录（pyproject.toml / uv.lock / .env / .gitignore）→ `LangChain入门笔记/` 系列目录 → `01-xxx/` 章节目录 → 代码文件 + `notebooks/` + `images/`，第一篇只展示这一小块、其余篇章略去；不能写成扁平 demo。正文的运行命令路径要和目录树自洽（从根目录用完整相对路径，或先 `cd` 进章节目录）。
- **示例保留 Agent 写法**：这个系列是"用 LangChain 构建 Agent"的教程。用户说"统一用 invoke"指的是**调用方式**（不用 stream/batch 等），不是调用对象；初始化等示例中的 `create_agent + agent.invoke` 要保留，不要为了强调模型调用而改成裸 `model.invoke`。消息类型示例这类本身是模型层面的可用 `model.invoke`。
- **单篇编号各自从 1 开始**：用户要求文章内部章节编号重新从 1 起（如第2篇用 `1.1`~`1.8`），不沿用目录序号（02）或旧稿遗留编号（3.x）。
- **示例脚本不要 main 函数**：教程配套的 .py 示例不要写 `def main()` 或 `if __name__ == "__main__":` 入口，代码直接写在模块顶层；正文代码块与脚本保持一致。
