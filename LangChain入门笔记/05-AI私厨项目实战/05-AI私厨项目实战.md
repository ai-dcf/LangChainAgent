# LangChain 入门笔记 05 - AI私厨项目实战

## 项目介绍

冰箱里还有两个鸡蛋、一个番茄，十分钟能做什么？

打开 AI 私厨，把食材打进聊天框，或者拍张照片发过去。页面会边生成边显示食材用量和步骤。想核对做法，就追问“帮我找一份有出处的番茄炒蛋做法”。下一轮只说“我只有十分钟”，它仍能接着刚才的食材往下答。

项目从 `v1-脚手架` 分支开始。仓库里已经有聊天页面、FastAPI 应用、请求模型和 OSS 签名接口。我们只需要填好项目根目录的 `.env`，再写两个文件。

- `app/agents/agent.py` 负责接收图文消息、调用模型和搜索工具、保存聊天记录。
- `app/api/v1/chat.py` 负责让页面调用它，包括发送消息、读取历史和清空会话。

下面以 Windows PowerShell 为例。正文给出两个文件的完整内容，可以一次复制、保存，再逐项验证。只需 DeepSeek API Key 就能跑通文字、搜索、会话和本地照片识别。想在页面上直接上传照片，再配置阿里云 OSS。

### 3. 写好 Agent

在项目根目录执行 `notepad app/agents/agent.py`。把整个文件替换成下面的代码。文件里的四段逻辑分别负责组装图文消息、按需搜索、按会话保存消息和流式返回正文。先原样保存，接通接口后再逐项试。

```python
import logging
import os
import sqlite3
from collections.abc import Iterator
from functools import lru_cache
from pathlib import Path

import requests
from dotenv import load_dotenv
from langchain.agents import create_agent
from langchain.messages import AIMessage, AIMessageChunk, HumanMessage
from langchain.tools import tool
from langchain_core.tools import ToolException
from langchain_openai import ChatOpenAI
from langgraph.checkpoint.sqlite import SqliteSaver
from langgraph.errors import GraphRecursionError
from openai import APIError

load_dotenv()
logger = logging.getLogger(__name__)

SYSTEM_PROMPT = """
你是一名家庭烹饪助手。根据用户已有的食材、口味和时间限制推荐菜谱。
收到照片时，先说明辨认出的食材，有疑问的部分请用户确认。
用 Markdown 写出菜名、食材及用量、操作步骤和预计耗时。
用户明确要求联网、核对做法或附上出处时，先调用 deepseek_web_search。
只引用搜索结果中实际返回的链接，搜索失败或没有结果时说明情况。
"""


@lru_cache(maxsize=1)
def get_agent():
    model = ChatOpenAI(
        model="deepseek-flash",
        base_url="https://api.deepseek.com",
        api_key=os.environ["DEEPSEEK_API_KEY"].strip(),
        use_responses_api=False,
        extra_body={"thinking": {"type": "disabled"}},
        timeout=60,
        max_retries=0,
    )
    return create_agent(
        model=model,
        system_prompt=SYSTEM_PROMPT,
        tools=[deepseek_web_search],
        checkpointer=checkpointer,
    )


def thread_config(thread_id: str) -> dict:
    return {"configurable": {"thread_id": thread_id}}


def stream_chat(agent, message: HumanMessage, thread_id: str) -> Iterator[str]:
    try:
        for part in agent.stream(
            {"messages": [message]},
            config=thread_config(thread_id),
            stream_mode="messages",
            version="v2",
        ):
            chunk, _metadata = part["data"]
            if isinstance(chunk, AIMessageChunk) and chunk.text:
                yield str(chunk.text)
    except (APIError, GraphRecursionError) as exc:
        status = getattr(exc, "status_code", None)
        logger.warning("生成回复失败（%s，HTTP %s）", type(exc).__name__, status)
        yield "\n\n这次没有生成完整回复，请稍后重试。"


def make_user_message(prompt: str, image_url: str | None) -> HumanMessage:
    url = (image_url or "").strip()
    if not url:
        return HumanMessage(content=prompt)

    return HumanMessage(content=[
        {"type": "text", "text": prompt or "请根据照片里的食材推荐一道菜。"},
        {"type": "image_url", "image_url": {"url": url}},
    ])


@tool
def deepseek_web_search(query: str, count: int = 5) -> dict:
    """搜索菜谱和烹饪资料，用于用户要求联网查询或提供来源的场景。

    Args:
        query: 由菜名、食材或做法组成的搜索关键词。
        count: 返回的结果条数，范围为 1 到 50。
    """
    query = query.strip()
    if not 1 <= len(query) <= 128 or not 1 <= count <= 50:
        raise ToolException("搜索词须为 1 到 128 个字符，条数须为 1 到 50。")

    try:
        response = requests.post(
            "https://api.deepseek.com/v1/tools/search",
            headers={"Authorization": f"Bearer {os.environ['DEEPSEEK_API_KEY'].strip()}"},
            json={"query": query, "count": count, "need_content": False},
            timeout=15,
        )
        response.raise_for_status()
        results = response.json()["results"]
    except (requests.RequestException, ValueError, KeyError) as exc:
        raise ToolException("网页搜索暂时不可用，请说明情况并给出一般做法。") from exc

    return {"results": [
        {"title": item["title"], "url": item["url"], "summary": item["summary"]}
        for item in results
    ]}


deepseek_web_search.handle_tool_error = True


db_path = Path(__file__).resolve().parents[2] / "db" / "personal_chief.db"
db_path.parent.mkdir(parents=True, exist_ok=True)
connection = sqlite3.connect(db_path, check_same_thread=False)
checkpointer = SqliteSaver(connection)
checkpointer.setup()


def get_messages(thread_id: str) -> list[dict]:
    checkpoint = checkpointer.get(thread_config(thread_id))
    if checkpoint is None:
        return []

    history = []
    for message in checkpoint["channel_values"].get("messages", []):
        if isinstance(message, HumanMessage):
            history.append({"role": "user", "content": message.content})
        elif isinstance(message, AIMessage) and message.text:
            history.append({"role": "assistant", "content": str(message.text)})
    return history


def clear_messages(thread_id: str) -> None:
    checkpointer.delete_thread(thread_id)
```

这里有三个地方值得对照着代码看。

- **图和问题一起发。** `make_user_message()` 把上传的图片地址和用户的提问放进同一条 `HumanMessage`。`deepseek-flash` 也可以直接读取一张 Base64 编码的图片，后面会用它在本地测试。 [DeepSeek 图片输入](https://api-docs.deepseek.com/guides/vision/)
- **问到出处才去搜。** `create_agent()` 注册了 `deepseek_web_search`。用户要求核对做法或提供链接时，模型生成搜索词，LangChain 执行工具，再把返回的标题、链接和摘要交给模型写答案。题目只有“晚饭做什么”时，可以根据已有食材直接答。 [DeepSeek 搜索 API](https://api-docs.deepseek.com/guides/search/)
- **只传这一轮，也能接上上一轮。** `stream_chat()` 给 Agent 一条新消息和 `thread_id`。SQLite 会读回这个 ID 的对话历史。模型边生成，函数边取 `AIMessageChunk` 的正文往外送。查询历史时会保留用户原来的图文消息，页面刷新后仍能显示先前的图片。 [LangChain 流式输出](https://docs.langchain.com/oss/python/langchain/streaming) · [LangChain 短期记忆](https://docs.langchain.com/oss/python/langchain/short-term-memory)

### 4. 把 Agent 接到页面

执行 `notepad app/api/v1/chat.py`，把文件原有内容全部替换成这一段并保存。已有的 `app/main.py` 会给路由补上 `/api/v1` 前缀。

```python
import os

from fastapi import APIRouter, HTTPException
from fastapi.responses import StreamingResponse

from app.agents.agent import (
    clear_messages,
    get_agent,
    get_messages,
    make_user_message,
    stream_chat,
)
from app.models.schemas import ChatRequest

router = APIRouter()


@router.post("/chat/stream")
def chat_endpoint(request: ChatRequest):
    if not os.getenv("DEEPSEEK_API_KEY", "").strip():
        raise HTTPException(status_code=503, detail="请先配置 DEEPSEEK_API_KEY。")

    message = make_user_message(request.message, request.image_url)
    chunks = stream_chat(get_agent(), message, request.thread_id)
    return StreamingResponse(chunks, media_type="text/plain")


@router.get("/chat/messages")
def get_chat_messages(thread_id: str):
    return {"messages": get_messages(thread_id)}


@router.delete("/chat/messages")
def clear_chat_messages(thread_id: str):
    clear_messages(thread_id)
    return {"success": True}
```

页面通过 `POST /api/v1/chat/stream` 发送本轮输入，通过 `GET /api/v1/chat/messages` 恢复历史，通过 `DELETE /api/v1/chat/messages` 清空指定会话。聊天接口回复的是逐块写出的 UTF-8 文本，页面会把它们接起来显示。

两个文件都保存后，在项目根目录先检查语法，再启动服务。

```powershell
uv run --locked python -m py_compile app/agents/agent.py app/api/v1/chat.py
uv run --locked python -m app.main
```

语法检查成功时没有输出。服务启动后，保留这个窗口，再开一个 PowerShell 窗口，进入同一个项目目录。

### 5. 用一组命令验证文字、搜索和记忆

在第二个 PowerShell 窗口粘贴下面这段。`-N` 让 curl 即时显示服务端写入的文本。函数固定使用一个会话 ID，所以下面的两次追问都能接着第一句说。

```powershell
$api = 'http://localhost:8001/api/v1'
$thread = 'wechat-' + [Guid]::NewGuid().ToString('N')
$utf8WithoutBom = [System.Text.UTF8Encoding]::new($false)
$OutputEncoding = $utf8WithoutBom
[Console]::OutputEncoding = $utf8WithoutBom

function Send-RecipeMessage {
    param(
        [string]$Message,
        [string]$ThreadId = $thread,
        [string]$ImageUrl
    )

    $body = @{ message = $Message; thread_id = $ThreadId }
    if ($ImageUrl) {
        $body['image_url'] = $ImageUrl
    }
    $body | ConvertTo-Json -Compress |
        curl.exe -sS -N -H 'Content-Type: application/json' --data-binary '@-' "$api/chat/stream"
    Write-Host
}

Send-RecipeMessage '我有鸡蛋和番茄，推荐一道晚饭。'
Send-RecipeMessage '帮我找一份有出处的番茄炒蛋做法。'
Send-RecipeMessage '只有十分钟，怎么做最快？'
```

第一条应逐步显示菜谱。第二条应附上搜到的做法链接，搜索失败时会说明情况。第三条应沿用鸡蛋和番茄。这三轮结束后，用下面的命令查历史，再清掉这个命令行测试会话。

```powershell
$historyUrl = "$api/chat/messages?thread_id=$thread"
(Invoke-RestMethod -Uri $historyUrl).messages | Format-Table role, content
Invoke-RestMethod -Method Delete -Uri $historyUrl | ConvertTo-Json -Compress
Invoke-RestMethod -Uri $historyUrl | ConvertTo-Json -Compress
```

清空接口应返回 `{"success":true}`，最后一次查询应返回 `{"messages":[]}`。如果聊天显示缺少密钥，检查项目根目录的文件名确实是 `.env`，修改后重启服务。如果服务窗口的警告出现 `HTTP 401` 或 `HTTP 402`，分别检查密钥和开放平台余额。

### 6. 先用本地照片测识别

准备一张 JPEG 食材照片，命名为 `ingredients.jpg`，放到项目根目录。在刚才定义了 `Send-RecipeMessage` 的窗口执行下面这段。请求把图片编码成 Base64，用一个新的会话 ID 发给模型。这一步可以直接观察照片识别，也可以用来区分问题出在模型还是网页上传。 [DeepSeek 图片输入格式](https://api-docs.deepseek.com/guides/vision/)

```powershell
$imagePath = (Resolve-Path -LiteralPath './ingredients.jpg').Path
$imageBytes = [IO.File]::ReadAllBytes($imagePath)
$imageData = 'data:image/jpeg;base64,' + [Convert]::ToBase64String($imageBytes)
$photoThread = 'photo-' + [Guid]::NewGuid().ToString('N')

Send-RecipeMessage -Message '看看照片里有哪些食材，再推荐一道菜。' -ThreadId $photoThread -ImageUrl $imageData
```

预期先看到模型说明它认出了哪些食材，接着是菜名和步骤。图片里有它拿不准的东西时，可以在提问里补一句是什么。

### 7. 让网页可以上传照片

想在页面点选文件时，再配置 OSS。上传由现有接口处理。页面先申请两个短期签名地址，用 `uploadUrl` 上传文件，然后把 `accessUrl` 发给模型读取。

1. 打开阿里云 OSS 控制台，在「Bucket 列表 → 创建 Bucket」建一个私有 Bucket。记下名称和地域 ID，例如杭州是 `cn-hangzhou`。 [OSS 控制台快速入门](https://help.aliyun.com/zh/oss/user-guide/get-started-with-oss/)
2. 在 RAM 控制台创建一个用于本项目的用户。在该用户的「凭证管理」创建 AccessKey。再到「权限管理 → 权限策略」新建自定义策略，在脚本编辑中复制下面的 JSON，把 `YOUR_BUCKET` 换成刚建的 Bucket 名。保存后，在该 RAM 用户页面通过「添加权限」授予这条策略。 [创建 AccessKey](https://help.aliyun.com/zh/ram/user-guide/create-an-accesskey-pair) · [创建自定义权限策略](https://help.aliyun.com/zh/ram/create-a-custom-policy)

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["oss:PutObject", "oss:GetObject"],
      "Resource": "acs:oss:*:*:YOUR_BUCKET/*"
    }
  ]
}
```

回到 Bucket，在「数据安全 → 跨域设置 → 创建规则」中，来源填 `http://localhost:8001`，允许 Methods 选 `PUT`，允许 Headers 填 `Content-Type`，保存。浏览器里也用这个地址打开页面，确保主机名和端口与规则一致。 [OSS 跨域设置](https://help.aliyun.com/zh/oss/user-guide/configure-cross-origin-resource-sharing)

打开项目根目录的 `.env`，保留已有的 DeepSeek 密钥，把 OSS 这几行替换成自己的配置。`OSS_ENDPOINT` 留空，由 SDK 按地域选择公网地址。

```dotenv
OSS_ACCESS_KEY_ID=你的RAM用户AccessKeyID
OSS_ACCESS_KEY_SECRET=你的RAM用户AccessKeySecret
OSS_BUCKET=你的Bucket名称
OSS_REGION=cn-hangzhou
OSS_ENDPOINT=
```

保存后在服务窗口按 `Ctrl+C`，重新运行 `uv run --locked python -m app.main`。测试时先请求一个签名，在终端只看三个字段是否拿到，签名地址也就无需复制出来。

```powershell
$signature = Invoke-RestMethod -Uri 'http://localhost:8001/api/v1/oss/presign?filename=ingredients.jpg'
[bool]$signature.uploadUrl
[bool]$signature.accessUrl
$signature.contentType
```

正常应输出两个 `True` 和 `image/jpeg`。现在刷新首页，点输入框里的图片按钮，选择一张 JPEG 照片，输入“帮我看看这些能做什么”并发送。签名接口返回 `503` 时，先核对 `.env` 和服务是否重启。签名能拿到但上传失败时，在浏览器开发者工具的「网络」里看 `OPTIONS` 和 `PUT`，检查 CORS、RAM 权限和请求的 `Content-Type`。照片读取签名默认有效一小时。旧照片地址过期后，点击「新建会话」再重新上传。

## 效果演示

打开 `http://localhost:8001/`，按这个顺序试一次。

1. **发一张食材照片，或者手打食材。** 选一张能看清鸡蛋和番茄的照片，问“这两样能做什么？”。页面应该先显示它认出的食材，再逐步补上菜谱。用文字输入时，可以直接写“我有两个鸡蛋和一个番茄”。
2. **让它找做法出处。** 追问“帮我找一份有出处的番茄炒蛋做法”。搜索有结果时，点开回复里的来源，看看它是否真的是对应的菜谱。
3. **补一个时间限制。** 接着说“我只有十分钟，怎么做最快？”。看它能不能沿用原来的食材，直接给出缩短后的步骤。
4. **刷新，再清空。** 刷新页面，继续看到刚才的对话。点击右上角「新建会话」后再问“我之前说了哪些食材？”，这时需要重新给它食材清单。

第三轮的回答可能是这样，供你对照页面效果。

> 可以做快手番茄炒蛋。先切番茄、打散两个鸡蛋。热锅把鸡蛋炒到刚凝固就盛出，用同一口锅炒番茄。番茄出汁后倒回鸡蛋，加盐翻匀。全程约 8–10 分钟。

我用独立的脚手架副本运行了正文里的代码和 PowerShell 命令。模拟服务下，文字分块、搜索与失败回退、同会话追问、历史查询和清空均通过，本地照片也能作为图文请求发出。上面的菜谱是预期示例。真实 DeepSeek 接口和 OSS 网页上传需要配置各自的密钥后验证。
